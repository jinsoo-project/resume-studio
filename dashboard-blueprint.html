Concept

콘텐츠는 한 번,
이력서는 여러 벌.

내용(경력·프로젝트·스킬)을 라이브러리에 한 번만 넣어두고, 대시보드에서 필요한 블록만 골라 조립한 뒤, 템플릿(원티드·리멤버·웹 포폴)을 입혀 각각의 URL로 발행하는 도구입니다. 지원하는 회사마다 다른 버전을 몇 초 만에.

01 LIBRARY

콘텐츠 라이브러리

02 BUILD

조립

→
03 TEMPLATE

공유 링크 + PDF. 공개/비공개.

Screens

대시보드를 이루는 4개 화면

빌더를 중심으로, 앞뒤로 라이브러리와 발행 관리가 붙습니다.

SCREEN 01

🏠 홈 · 내보낸 이력서

발행한 이력서 카드 목록(제목·템플릿·URL·공개상태·최근수정). "새 이력서 만들기" 버튼. 여기서 링크 복사·PDF·삭제.

SCREEN 02

📚 콘텐츠 라이브러리

프로필·경력·프로젝트·스킬·학력·수상을 블록으로 CRUD하는 단일 원본. 한 번 잘 써두면 모든 이력서가 여기서 나옴.

SCREEN 03

🧩 빌더 (위 목업)

블록 선택·순서·강조 + 템플릿 + URL. 지원처별 맞춤 이력서를 조립하는 핵심 화면.

SCREEN 04

🌐 공개 뷰 (발행 결과)

방문자가 URL로 보는 페이지. 템플릿에 따라 웹 포폴(03)이거나 A4 이력서. 인쇄→PDF 지원.

Decision

이제 정할 것 — 어디까지 만들까

"URL로 발행 + 편집 + 관리"를 어떻게 구현하느냐가 갈림길입니다. 이 PC엔 Node가 없어서, 그 점도 고려한 두 갈래.

추천 · 지금 가능

A. 정적 빌더

브라우저 안에서 도는 대시보드 (백엔드 없음)
  • 편집 내용은 브라우저 저장(localStorage) + 파일로 내보내기/가져오기
  • 발행 = 조립본을 URL에 인코딩하거나, 정적 파일로 Vercel에 올림
  • Node·서버·Supabase 불필요 — 지금 바로 제작·배포 가능, 무료
  • 한계: 여러 기기 동기화·깔끔한 짧은 URL·중앙관리엔 약함
본격 제품

B. 풀 앱

Next.js + Supabase + Vercel
  • DB에 문서 저장 → 깔끔한 슬러그 URL(/r/handys), 어디서나 로그인 편집
  • 공개/비공개·조회수·버전관리까지 "진짜 서비스"급
  • 이 경우 Supabase가 비로소 필요해짐 (지금까진 불필요했던 이유가 이것)
  • 필요: Node 설치 또는 클라우드 빌드. 제작 비용 ↑

제 추천: A로 뼈대(라이브러리·빌더·미리보기·템플릿 전환)를 먼저 완성해서 흐름을 확정한 뒤, 필요해지면 B로 승격(같은 데이터 모델이라 이전이 쉬움). 지금 만든 3개 파일이 그대로 "템플릿"으로 들어갑니다.
